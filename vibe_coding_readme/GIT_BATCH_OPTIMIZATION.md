# Git批量命令优化方案 (方案1) - 详细说明

## 🎯 方案概述

方案1使用Git批量命令优化来替代逐个执行`git show --stat`，特别针对32k+提交的大型仓库进行性能优化。

## 🚀 核心优化策略

### 1. 智能方法切换
- **小型仓库** (≤1000提交): 使用原始的逐个处理方法
- **大型仓库** (>1000提交): 自动切换到优化的批量方法

### 2. 批量Git命令
```bash
# 原始方法（慢）：对每个提交执行
git show --stat --format= <hash1>
git show --stat --format= <hash2>
git show --stat --format= <hash3>
...

# 优化方法（快）：单个命令处理多个提交
git log --stat --format=%H --no-merges <hash1> -1 <hash2> -1 <hash3> -1 ...
```

### 3. 分块处理
- 最大批次大小：5000个提交
- 避免命令行长度限制
- 防止内存溢出问题

## 📊 进度显示机制

### 实时进度反馈
```go
progressCallback := func(current, total int, message string) {
    percentage := float64(current) / float64(total) * 100
    fmt.Printf("\r⏳ [%.1f%%] %s", percentage, message)
}
```

### 进度阶段
1. **初始化阶段**: `开始优化批量处理...`
2. **分块处理**: `处理提交块 1-5000/32000...`
3. **Git命令执行**: `执行Git命令获取 5000 个提交的统计信息...`
4. **数据解析**: `解析 5000 个提交的统计信息...`
5. **完成反馈**: `完成提交块 1-5000/32000`
